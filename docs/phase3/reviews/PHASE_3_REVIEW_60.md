### Correction 1 (P2): §4.4 states two conflicting override target-domain rules, leaving the reserved intrinsic namespace unprotected on one of them

- **File:line:** `docs/phase3/v1/PHASE_3_DOC.md:2313-2318` (blocklist + action matrix + validation order), conflicting with `:2357-2358` (whitelist), and the invariant it fails to enforce at `:2545`.
- **Failure path:** line 2313 states "Overrides cannot target standard A–G, `SCHMALOOGIUM_VERSION`, option macros, or the reserved contributor namespace. For every other valid name, the complete action matrix is: … ADD → insert the supplied replacement." Under that rule a `RuntimeIdentityData.perPackIdentityOverrides` entry `ADD __VERSION__ <replacement>` (or `__FILE__`, `__LINE__`, `GL_core_profile`, `GL_compatibility_profile`, `GL_ARB_geometry_shader4`) passes every listed check — valid identifier, non-null replacement, not a protected target, name absent after the base merge — and is inserted into the merged environment. §4.5 (lines 2540–2547) has the jcpp wrapper unconditionally supply those same names and declares "Reserved intrinsic names cannot be overridden/undefined", but that sentence covers only "pack or contribution input"; the per-pack override channel is the third input path. The result is either a silent double definition with library-order-dependent winner or a wrapper exception surfacing as source-local `Unavailable`/`UNEXPECTED_INTERNAL` — an outcome the document does not define. Line 2357 separately says "`perPackOverrides` is limited to non-version identity/capability names", a *whitelist* under which the same request is `INVALID_REQUEST`; the two rules classify the identical request differently, and the validation-order sentence (2316–2318, which checks "protected target") does not say which governs. Arbitrary non-identity/capability names (e.g. `ADD FOO`) are similarly admitted by 2313 and rejected by 2357.
- **Owner/receiver:** Owner is Phase 3 §4.4 (binding through the §5.1 `MacroConfiguration` row's "Full merge/override validation/action order" incorporation and §12 item 6). No receiver currently supplies overrides, so no receiver-side change is required; this is a producer request-validation correction with no `PackConfiguration` component, meaning or fingerprint change, hence no schema bump (same class as Rounds 50/51).
- **Minimal resolution:** make one rule authoritative — state in §4.4 that the protected-target check enforces the line-2357 whitelist (override targets are exactly non-version identity/capability names), that the action matrix's "every other valid name" means every name admitted by that whitelist, and that the §4.5 reserved intrinsic namespace is rejected with the same pre-I/O `INVALID_REQUEST`; extend `macroConfiguration_overrideActionTargetMatrixAndPrecedence` (§8.1, lines 4696–4698) with a reserved-intrinsic/arbitrary-name rejection case, and add the required explicit §5.1 row entry for the changed incorporated validation semantics per §5.1's own edit rule.
