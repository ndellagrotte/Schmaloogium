## Substantive corrections

### 1. C44-1 — Preserve one unambiguous allocation-fallback trigger contract

- **Severity:** P2 / substantive contract inconsistency.
- **Primary location:** `docs/phase5/v1/PHASE_5_DOC.md:1766–1769`.
- **Conflicting active locations:** `docs/phase5/v1/PHASE_5_DOC.md:1830–1834,2982–2986`; incorporated clear contract at `:2662`.
- **Defect:** D-P5-46 says existing whole-estate RGBA fallback remains *exclusive* to the completeness-failure path. However, the active allocation state machine explicitly requires that same single fallback after a facade allocation error attributed to a candidate color texture or an internal-format capability rejection, in addition to an incomplete FBO. The failure-mode table independently preserves allocation-error fallback. None of those active clauses is marked superseded. The new sentence therefore narrows more than its preceding, valid exclusion of missing integer-clear capability.
- **Observable consequence:** when a requested color allocation fails before an FBO completeness check—for example, a noninteger requested format's texture allocation reports a format-related error—the owner simultaneously forbids and requires the RGBA retry. An implementation following the new exclusive clause would turn shaders off where §4.7 requires one whole-estate RGBA attempt; following §4.7 would violate the incorporated new clause. This affects whether candidate creation can reach Ready, not merely diagnostic wording.
- **Minimal owner fix:** replace the completeness-exclusive sentence with an explicit reference preserving §4.7's existing allocation-error, incomplete-FBO and internal-format-capability fallback triggers, while keeping absence of the required integer-clear tier a separate preallocation hard rejection that cannot be hidden by fallback. Retain realized-format recomputation after successful fallback. No new API, fallback attempt or receiver protocol is necessary.
- **§5 impact:** **Yes.** The corrected §4.6 semantics are expressly incorporated by §5.1's clear row. Reconcile the owner in one edit rather than leaving competing implementable branches.
